# 美股 Renko 日內趨勢交易模型草案

版本：1.0｜日期：2026年10月14日｜市場：美股｜計價：美元｜交易時間：America/New_York

這套模型將手寫簡報的五個階段整理成「篩選股票池 → 分時段揀股 → 配置資金 → 判斷是否開市交易 → 順勢持倉及反手」。目標是找出有足夠流動性、日內波幅及較少方向反覆的股票，以第一個確認的價格磚塊決定方向，同方向繼續持有，反方向先平倉再反手，每個時段結束前清倉。

用戶已確認美股及反手模式。其他新增數值均為研究起點，並非已驗證的最佳參數。現有來源只有五張策略照片，沒有行情、歷史成交或本金資料；本版本完成的是模型設計及驗收規格，未有盈利、勝率或回撤實測結果。配套 JSON 是參數草案，不是交易程式。

## 1 草稿檢視及修訂

| 原有構思 | 檢視結果 | 本模型的處理 |
|---|---|---|
| 過去20日、1分鐘數據；市值大於 US$2B | 可作流動性股票池的起點；市值仍需獨立資料 | 保留20個已完成交易日，用當時可取得的市值及價格資料 |
| 平均每日成交量大於1,000萬股 | 股數不能直接代表可成交金額 | 保留原門檻，額外記錄成交額、買賣差價及分鐘成交量 |
| 平均每日高低幅度大於1.5% | 未定義百分比的分母 | 用每日 `(高−低)/前一日收市價`，再取20日平均 |
| 平均股價約 US$20–1,000 | 下限有刪改，暫讀作20 | 以20–1,000作參數；另要求前一日收市價也在此範圍 |
| 0.5% Renko，亦容許固定美元磚塊 | 磚塊大小及反向門檻未定義 | 每日以前收市價的0.5%定出固定美元磚塊；反向1磚為主版本，傳統2磚另作比較 |
| 揀最高 RR 的10隻股票 | RR可以用很少樣本得到很高值 | 分AM、PM各選最多10隻，加入最低磚塊數及資料完整度要求 |
| 個股 RR = 磚塊數 / (1＋反向次數) | 與第三頁組合 RR 的分母不一致 | 全部使用相同平滑方法；組合 RR = Σ磚塊數 / Σ(1＋反向次數) |
| 用 US$1,000及 LCM 定注碼 | 不同股價沒有合理的最小公倍數配置關係 | 用股數向下取整，並受每筆風險、總倉位及購買力限制 |
| 當日 RR 不低於前日才交易 | 全日與30分鐘不能直接比較；等號亦出現在兩個分支 | 只比較同一批股票、同一30分鐘、同一算法；大於或等於才通過 |
| 上午9:00–9:30觀察，9:30開始 | 在美股屬盤前，不是正規交易 | 主版本改9:30–10:00觀察、10:00開始；原盤前版本另列實驗 |
| 反向即止蝕，或平倉再反手 | 兩者產生不同交易路徑 | 主版本先平再反手；只平倉版本作對照；反向平倉亦可能鎖定盈利 |
| 時段完結全部賣出 | 淡倉應買入平倉，且終點價格不保證成交 | 長倉賣出、淡倉買回；以實際成交或有成本的下一可用價格計損益 |

RR 在這裏是草稿的 Renko Ratio，稱為「走勢持續度」，不是風險回報比，也不是勝率。高 RR 是否對下一時段有預測能力，必須獨立驗證。

## 2 時間及資料規則

### 2.1 主版本交易時段

美股正規交易時段為紐約時間9:30–16:00，按交易所日曆處理假期及提早收市。[NYSE 交易時間](https://www.nyse.com/trade/hours-calendars)

| 工作 | AM | PM |
|---|---|---|
| 前日揀股評分窗口 | 前日10:00–12:30 | 前日13:00–16:00 |
| 當日觀察窗口 | 9:30–10:00 | 12:30–13:00 |
| 用作對比的前日觀察窗口 | 前日9:30–10:00 | 前日12:30–13:00 |
| 建立交易價格錨點 | 10:00第一個有效分鐘開市價 | 13:00第一個有效分鐘開市價 |
| 可接受新訊號 | 10:00–12:20之前 | 13:00–15:50之前 |
| 預定平倉指令 | 12:25 | 15:55 |
| 絕對時段終點 | 12:30 | 16:00 |

窗口採用左閉右開，例如9:30–10:00包括9:30開始的分鐘，不包括10:00開始的分鐘。分鐘資料須同時記錄開始及完結時間；9:59開始的 bar 要到10:00才完整可用。沒有足夠執行時間的終點訊號一律忽略。

半日市主版本只運行 AM；距實際收市前5分鐘或12:25兩者較早者開始清倉。停市日不運行。因停牌未能清倉，要列為異常及隔夜風險，不能假設已在指定價成交。

草稿的9:00–9:30觀察／9:30入市只作盤前實驗版本；必須取得盤前數據、以前日同一盤前窗口作比較，並獨立驗證開市成交。主版本延遲上午入市是為了使用正規時段觀察數據，並非聲稱10:00較有盈利能力。

系統保存 UTC 時間，交易規則轉換至 America/New_York；香港介面轉換至 Asia/Hong_Kong。採用時區資料庫處理夏令時間，不寫死香港開市鐘數。

### 2.2 所需數據

| 類別 | 必需欄位及用途 |
|---|---|
| 股票及上市歷史 | 當日可交易代號、證券類型、上市／除牌日期；保留歷史除牌股 |
| 一分鐘行情 | 時間、open、high、low、close、volume；產生訊號及初步成交模擬 |
| 日線 | 前收市價、每日高低、每日成交股數、成交額；篩選及磚塊大小 |
| 市值及公司行動 | 當時可知的市值、拆股、合股、除息、代號變動；避免拆股假訊號 |
| 買賣報價 | bid、ask、報價時間及可用量；成本及實盤驗證 |
| 券商資料 | 佣金、費用、可沽空量、借貨費、購買力、下單／成交／拒單事件 |
| 事件日曆 | 當時已公布的業績時間、交易所假期、停牌及沽空限制 |

研究股票池先限美國交易所上市普通股；ETF、槓桿產品、OTC及其他證券類型分開研究。20日資料齊全才篩選；候選股票相關分鐘窗口完整度至少99%，但對觀察窗口或持倉期間的任何未解釋缺失，停止新倉並標示資料異常。供應商須分辨真實無成交分鐘及傳輸缺失，不把缺失分鐘補成假成交。

篩選可用一致基準的拆股調整數據；歷史訂單、成交、股數及損益使用當日原始價並正確處理公司行動。沒有前收市價／市值／借貨等必要輸入，應有明確排除原因。

## 3 階段一 股票池篩選

在交易日 D 開始前，以 D−20 至 D−1 的20個已完成交易日計算：

```text
ADV20       = mean(每日成交股數)
Range20     = mean((每日最高價 − 每日最低價) / 該日前收市價)
AvgPrice20  = mean(每日收市價)
DollarADV20 = mean(每日成交額)

納入條件：
  D−1 當時可知市值 > US$2,000,000,000
  ADV20 > 10,000,000 股
  Range20 > 0.015
  20 <= AvgPrice20 <= 1,000
  20 <= D−1 收市價 <= 1,000
  所需數據完整，證券類型符合
```

計20日幅度需要窗口之前的一個收市價。草稿的「過去20日」在此解作交易日，而非曆日。市值不是從分鐘OHLC推算；使用截至當時可取得的市值，並記錄發布／可取得時間。

市值採用前日最新已知快照，其餘篩選統計採20日平均；這是本版的明確選擇。若原稿的「average data」亦指平均市值，可另測20日平均市值版本。

每天輸出納入股票、全部篩選值及未納入原因。當日已知有業績公布或公司行動而無法可靠處理的股票，研究主版本剔除；此事件規則只使用決策時已知資料。

## 4 階段二 Renko 定義及揀股

### 4.1 磚塊大小

以交易日 D 的前收市價 Pprev 及該股票當日有效最小價格跳動 tick 計：

```text
b(D) = ceil(0.005 × Pprev / tick) × tick
```

磚塊 b 是美元金額，當日固定，不隨最新股價、事後數據或圖表重載改變。歷史日 D−1 使用它當日已知的 b(D−1)，不能把今日磚塊回填昨天；兩日均使用相同百分比設定。固定美元模式另作參數比較，不混用排行榜。

分鐘收市價只在該分鐘完成後產生確認訊號。初始錨點為窗口首個有效分鐘開市價，方向 d=0；選股、觀察及實際交易的每個窗口各自重設，避免將跨窗口／隔夜跳空當作持續磚塊。

### 4.2 主版本一磚反向算法

令 c 為最後確認磚塊終點，p 為最新已完成分鐘收市價：

```text
初始 c = 窗口首分鐘開市價，d = 0
當 p >= c + b：產生一個向上磚塊，c = c + b，d = +1
當 p <= c - b：產生一個向下磚塊，c = c - b，d = -1
重複上述步驟，直到 abs(p-c) < b
只有舊 d 不為0且新 d 與舊 d 相反，才累加一次反向
恰好達門檻亦確認；實作以整數 tick 避免浮點邊界錯誤
```

這是沿用草稿「每次變動達門檻」的自訂一磚方向模型。傳統 Renko 常要求反方向移動兩磚才生成反向磚；兩者不可視作同一策略。[TradingView Renko 定義及例子](https://www.tradingview.com/support/solutions/43000502284-understanding-renko-charts/)

傳統2磚比較版本：同方向每 b 一磚；反方向至少2b，首個反向磚終點是 c−2b（原上行）或 c＋2b（原下行），首個反向磚只計一個，其後每 b 一磚。未達反向2b時保持原方向。測試時連同止蝕距離一起記錄，不能只更改磚塊圖。

同一分鐘可以生成多個磚塊，但都是在該分鐘完成後才知道。全部磚塊用於統計，交易層只對該時間點的最後方向作一次決策；不模擬在該分鐘各個合成磚價逐次成交。收市價模型不能重建分鐘內先升後跌的路徑，tick／報價重播須作獨立驗證。

### 4.3 RR 及排行榜

```text
B = 該窗口確認磚塊總數
R = 磚塊方向轉換次數；每個窗口第一磚不算反向
RR = B / (1 + R)
```

例如方向 `↑ ↑ ↑ ↓ ↓ ↑`，B=6、R=2、RR=2。`↑ ↑ ↑ ↑ ↑ ↑` 的 B=6、R=0、RR=6。這是算法例子，並非歷史觀察。

在 D−1 收市及數據驗證後，分別按 AM、PM 評分窗口的 RR 遞減排列。先要求 B≥3（待驗證起點），再用較高成交額、較小可知差價、代號字母次序依次處理同分；沒有差價資料時不使用該同分項，但必須標記成本證據不足。取各自最多10隻，不足10隻就保留實際數目，不放寬篩選湊數。選股表於 D 開市前固定，PM 也不使用當日後來的走勢重排。

上一日高 RR 不保證今日高 RR。多日穩定度版本可另用過去5個相同時段的 ΣB/Σ(1＋R) 排序；它屬對照實驗，不能在看過結果後悄悄替換主版本。

## 5 階段三 資金配置

### 5.1 股數及風險公式

US$1,000 是每個倉位的目標名義金額，不是可承受損失，也不是整個賬戶本金。設 E0 為當日開始時賬戶淨值，P 為預計可成交價，Dstop=2b 為初始緊急止蝕距離，Cps 為每股預估來回成本：

```text
每筆風險額 r = 0.001 × E0
q_notional   = floor(1,000 / P)
q_risk       = floor(r / (Dstop + Cps))
q_cap        = floor((0.10 × E0) / P)
q_liquidity  = floor(0.01 × 最新已完成分鐘成交量)
q            = min(q_notional, q_risk, q_cap, q_liquidity,
                   券商購買力容許股數, 可借股數如沽空)
```

美股主版本以整股交易；q<1不交易。已完成分鐘成交量是下單前可知的代理量，不能使用下一分鐘最終成交量來決定訂單。真實執行仍需檢查當時可用報價量及部分成交。

例如 P=50、b=0.25，只考慮名義金額會得20股、US$1,000；2b初始止蝕的價格風險是US$10，再加成本。若風險或購買力只容許較少股數，就縮小。這些數字只示範計法。

配置採用當日 E0，不因早段盈利而即日提高風險預算。淡倉售股所得不當作新增可自由使用本金。反手重新計 q，不必與原倉同股數；不加注攤薄虧損。

### 5.2 組合限制

| 控制項 | 研究起點 |
|---|---|
| 候選股 | AM、PM各最多10隻 |
| 同時持倉 | 最多5隻 |
| 單股名義倉位 | 不高於 E0 的10%，且不超過US$1,000目標 |
| 總名義敞口 | Σ絕對倉位市值不高於 E0 的50% |
| 行業名義敞口 | 任一行業不高於 E0 的20% |
| 總預算止蝕風險 | Σ開倉／剩餘預算風險不高於 E0 的0.5% |
| 全日損失開關 | 淨已實現＋可平倉價計未實現損益≤−1% E0，平倉及當日停機 |
| 單股每時段最多反手 | 3次；其後再反向只平倉並鎖定該股至時段完結 |

同一分鐘多個候選訊號以預先固定的排行榜順序分配有限倉位。提交中的訂單亦佔用風險及購買力預算，避免多個訂單各自看似合格但合共超標。

止蝕及日損上限是指令觸發／預算控制，不保證損失封頂；跳空、停牌及滑價均可能超過預算。本金尚未提供，實盤啟用前必須設定 E0、賬戶類型及券商購買力。

## 6 階段四 決定當日是否交易

對某時段已固定的 n 隻候選股，分別在當日及前日同一觀察窗口計：

```text
BasketRR = Σ B_i / Σ(1 + R_i) = Σ B_i / (n + Σ R_i)
GatePass = 當日 BasketRR >= 前日 BasketRR
```

不使用原第三頁 ΣB/ΣR，因為 R=0時無法計算；也不取個股 RR 的簡單平均。保留每隻股票 B、R、RR及組合總數，以免單一活躍股票掩蓋其他股票反覆。

觀察窗口兩日須使用完全相同的候選列表。任何股票缺完整窗口資料，該時段不開新倉；不為取得通過結果即場刪除股票。兩日各要求 ΣB≥2n，當日每隻股票另需 B≥1；都是待驗證的樣本門檻。RR不通過、樣本不足或 n=0，一律跳過該時段。

AM開關只決定AM；PM開關重新計算。全日風險開關優先，上午觸發日損停機後下午不能重啟。主版本開關在觀察結束時決定一次，該時段不再按最新RR反覆開關；持倉由交易及風險規則管理。

前日觀察資料可能參與當日排名的研究解釋，但不是獨立統計驗證；開關是否有效要靠樣本外「開關啟用／關閉」對照。

## 7 階段五 入市 持倉及反手

交易窗口開始時重設價格錨點，不沿用觀察窗口的最後磚塊。等待第一個已完成分鐘確認磚塊，上行買入、下行沽空。若首方向向下而當時不能沽空，留空倉；不以其他工具代替，後續上行訊號可再檢查買入資格。

| 當前狀態 | 新確認方向 | 動作 |
|---|---|---|
| 空倉且可開倉 | 上行 | 通過成本及風險檢查後開長倉 |
| 空倉且可開倉 | 下行 | 通過借貨、成本及風險檢查後開淡倉 |
| 長倉 | 上行 | 持有，不增加股數 |
| 淡倉 | 下行 | 持有，不增加股數 |
| 長倉 | 下行 | 先賣出平倉，確認平倉後再申請沽空 |
| 淡倉 | 上行 | 先買回平倉，確認平倉後再申請買入 |
| 任一持倉 | 時間平倉／緊急止蝕／日損停機 | 取消未成交新倉單，平倉；不反手 |

反向不一定等於虧損：趨勢延伸後的反向退出可以有盈利。反手計作兩項成交及相應費用。未確認舊倉清零、部分成交、借貨不足或平倉拒單時，不開新方向；先核對券商實際倉位。

### 7.1 緊急止蝕與反手的優先次序

每次新倉按實際成交均價 Pe 設長倉 Pe−2b、淡倉 Pe＋2b 的初始緊急止蝕，2b為待驗證起點；主版本不設固定止賺或額外移動止蝕，以便隔離原有順勢反手規則。緊急止蝕觸發後該股該時段停用，避免把緊急退出立即變成反手。

依次處理：已生效止蝕／全日停機 → 預定時間平倉 → 舊單成交核對 → 新分鐘訊號 → 新倉檢查。新訊號只在沒有更高優先退出原因時執行。

初步回測只用前一時點已知止蝕檢查下一個普通 OHLC bar；若價格跳過止蝕，按更差的可成交價及滑價，而不是固定止蝕價。若同分鐘既觸止蝕又有方向訊號，保守按先止蝕及停用處理，不自行假設有利的分鐘內次序。

### 7.2 訊號及成交

分鐘 t 的確認訊號，最早在它完結後才可提交；初步回測以普通OHLC的下一分鐘 open加不利成本模擬，實盤按收到訊號後的 bid／ask及成交記錄。設定延遲、部分成交、拒單及撤單處理。反手回測如共用下一分鐘可成交時間，仍分開記錄先平及後開兩筆，成本各自計算。

Renko 磚塊價是合成訊號水平，不是保證可成交價格；直接用磚塊价回測會失真。[TradingView 合成圖表回測限制](https://www.tradingview.com/support/solutions/43000481029-strategy-produces-unrealistic-results-on-non-standard-chart-types-heikin-ashi-renko-etc/)

## 8 交易成本及執行條件

淨損益＝Σ〔方向 × 股數 ×（平倉價−開倉價）〕−佣金−交易費−借貨費−其他實際成本。若成交價已包含 bid／ask差價及滑價，不再重複扣同一項成本。

主版本每筆新倉要求估計每股來回成本≤0.25b；成本資料不足時，只能做有清楚假設的探索回測，不能當作已通過實盤驗收。測試基準成本、2倍及3倍成本，並報告成本吃掉的毛利比例及反手所增加的成本。

沽空須確認賬戶權限、可借量、借貨費及當時適用限制；不能假設每隻股票在每個歷史時點都能沽空。沽空股價上升可能令損失超過原投入額。[SEC 投資者沽空介紹](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins-51)

截至2026年10月14日，FINRA新的日內保證金規則已於6月4日生效，券商實施過渡期至2027年10月20日。不能一概假設所有賬戶仍須舊制US$25,000門檻，也不能假設自己的券商已取消舊制；必須以實際券商採用制度、賬戶類型及購買力判定。[FINRA Regulatory Notice 26-10](https://www.finra.org/rules-guidance/notices/26-10)

## 9 回測設計及驗收

### 9.1 待驗證假設

| 假設 | 對照及判斷方法 |
|---|---|
| 前一時段高 RR 能識別下一日較適合趨勢交易的股票 | 最高RR候選與同股票池、同成本／資金限制的固定或重複隨機候選比較 |
| 日內RR開關能避開反覆市況 | 完全相同候選及訊號，開關啟用與關閉比較淨損益及回撤 |
| 反手能捕捉新方向且值得支付成本 | 即時反手與「只平倉、到下一分鐘之後的下一個確認磚才重新申請」比較 |
| 0.5%磚塊有合適訊噪比 | 與預先限定的0.25%、0.75%、1.0%比較；不同反向算法分開呈報 |
| 上午及下午規律足夠穩定 | 分別報告AM、PM及全日，不用合計盈利遮蓋虧損時段 |

### 9.2 測試次序

1. 先用人工價格序列核對磚塊、門檻等號、零反向、同分鐘多磚、反手、部分成交、止蝕、半日市及數據缺失。
2. 收集建議至少12個月的歷史分鐘數據，條件容許以24個月及多種市況為目標。20日只是篩選窗口，不能當驗證期間。
3. 按時間先後分訓練、驗證及最後封存樣本外期間；例如60%／20%／20%，保留每段開始前所需的暖機歷史。最後20%不用於參數選擇。
4. 在前80%做滾動測試，例如過去6個月設定、下1個月驗證。每天按當時可知資料重做篩選及名單；保留除牌股票、交易限制及公司行動。
5. 先做RR揀股、開關、反手三項對照，再測小範圍參數；完整保存試過的版本，避免只展示贏家。最後一次使用封存樣本外期間驗收。
6. 獨立做成本、延遲及借貨限制壓力測試，並至少30個交易日模擬交易核對真實訊號與成交；30日只是起點，訊號少或市場單一時延長。

資料不足一分鐘內路徑／歷史借貨時，明確標記限制；不能把收市價近似模型稱作tick精度回測。

### 9.3 必須報告的指標

淨累計損益、相對E0／每日淨值的回報、最大回撤金額及百分比、每日收益波動、淨勝率、平均盈虧、Profit Factor、每筆淨期望值、交易／反手次數、成交率、滑價、成本佔毛利、持倉時間、沽空失敗率、被開關跳過的時段，以及RR與下一時段淨收益的關係。

勝率以已完成的一段倉位計，反手結束舊倉並開一段新倉；同時另報按股票時段及按日的結果。Profit Factor＝總正淨損益／總負淨損益絕對值，無負值時標記不適用而不當作成功證據。沒有獨立日樣本或樣本過少時，不提供有誤導性的年化結果。

每項結果分AM／PM、長／淡、股票／行業及市況；列出樣本數。信賴區間以交易日／時間區塊抽樣，避免將同日高度相關交易當作獨立樣本。

### 9.4 啟用條件

| 檢查 | 所需證據 |
|---|---|
| 計算可重現 | 相同數據、參數及版本可重建名單、訊號、訂單及損益 |
| 樣本外經濟價值 | 扣實際成本後淨期望值及Profit Factor有改善，並提供不確定性；不是只看毛利或勝率 |
| 對照價值 | RR揀股、開關及反手的效果各自有紀錄，能分辨哪個組件有效 |
| 風險符合承受能力 | 最大可接受回撤金額及百分比由用戶填寫；未填寫不啟用實盤 |
| 壓力及穩定性 | 成本、延遲、相鄰參數及不同時段／市況下表現可理解，沒有單一股票支撐全部盈利 |
| 模擬交易可操作 | 訊號與回測一致，拒單、借貨、部分成交及斷線均能恢復及核對 |

若反手或開關在樣本外無改善，就保留原始結果並採用更簡單的有效版本；不以追求草稿形式為理由保留已證實無效的組件。現階段以上驗收尚未執行。

## 10 實施及記錄

開發可分六個組件：行情及日曆、股票池篩選、Renko／RR、排行榜及開關、風險及訂單、損益及審計。第一步只做歷史回放和模擬交易；實盤需要券商連接及上述驗收。

每天至少保存以下表格：

| 表格 | 核心欄位 |
|---|---|
| universe_daily | 日期、代號、市值、ADV20、Range20、價格、納入／排除原因 |
| selection_slots | 交易日、AM／PM、評分日及窗口、b、B、R、RR、名次 |
| gate_slots | 候選列表、當日／前日B及R、BasketRR、樣本門檻、通過／跳過原因 |
| signals | 確認時間、方向、磚塊數、最新c、當時可知數據時間 |
| orders_fills | 訂單及關聯平倉ID、提交／成交時間、方向、股數、價格、成本、拒單／部分成交 |
| risk_daily | E0、總／行業敞口、保留風險預算、淨損益、停機原因、未平倉異常 |
| performance | 倉位段／時段／日結果、版本、參數、數據來源及限制 |

完成交易日後核對券商倉位與內部賬本，記錄所有偏差；參數改動只從下一個完整測試版本生效，保留舊結果。
